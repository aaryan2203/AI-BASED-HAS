01 // SYSTEM OVERVIEW

What is BAS-HAR?

BAS-HAR is an AI-powered Human Activity Recognition prototype designed to analyze activity sequences from video without depending on cloud-based inference.

🛰️

Offline Intelligence

The recognition pipeline is designed to run locally on a standalone computer. Video does not need to be continuously uploaded to a remote server for inference.

👤

Human Activity Recognition

The system converts visual human movement into temporal features and uses an LSTM model to classify activity patterns across multiple video frames.

🧠

AI-Based Processing

YOLO pose estimation provides human keypoints, while a deep learning sequence model learns how movement evolves over time.

📹

Video Processing

The system can process recorded video and can also operate through the graphical interface for visualizing predictions and activity timelines.

⚡

Real-Time Pipeline

Pose detection, feature extraction and temporal inference are combined into a continuous recognition pipeline.

🔬

Experiment Monitoring

The long-term goal is to recognize predefined experiment activities and provide local activity validation during experimental procedures.

02 // MISSION CONTEXT

Problem & Solution

THE PROBLEM

  • Continuous transmission of raw video can require significant communication bandwidth.
  • Remote environments may have communication delays or intermittent connectivity.
  • Manual monitoring of long experimental procedures can be difficult.
  • A generic activity-recognition model may not understand experiment-specific activities.
  • Object interaction and human movement must be considered together for future BAS-specific recognition.

THE BAS-HAR APPROACH

  • Process the video locally instead of depending on cloud inference.
  • Use pose estimation to represent human movement.
  • Convert consecutive frames into temporal feature sequences.
  • Use an LSTM to recognize activity patterns over time.
  • Use confidence filtering so uncertain predictions can be shown as Unknown.

🔄

Temporal Learning

Instead of classifying one isolated frame, the LSTM receives a sequence of frames and learns movement patterns over time.

🎯

Confidence Filtering

Predictions below the configured confidence threshold can be reported as Unknown instead of presenting a low-confidence activity as a reliable result.

💾

PyTorch Model

The trained network is stored as a PyTorch .pth model and loaded locally during inference.

05 // CURRENT PROTOTYPE

Recognized Activities

The existing prototype model contains four generic human activity classes.

🚶

Walking

Movement pattern corresponding to a person walking through the observed environment.

🧍

Standing

Stationary upright posture detected over the temporal sequence.

🪑

Sitting

Temporal pose pattern associated with a seated person.

🤚

Reaching

Movement pattern associated with extending the body or arms toward an object or location.

Prototype Model Status

The current model is a pipeline-validation model rather than the final BAS-specific activity model. Its observed best validation accuracy was approximately 31.71%. The next development stage is to create a proper BAS-specific dataset and retrain the model using experiment-specific activity classes.

06 // DATA ENGINEERING

BAS Dataset

The quality of the final recognition system depends heavily on correctly labeled and sufficiently varied activity videos.

DATASET PRINCIPLES

  • Each video should represent the activity indicated by its folder.
  • Do not place the same video into multiple activity folders with different labels.
  • Capture different body positions, speeds and viewpoints.
  • Include variations in lighting and environment where possible.
  • Keep a separate collection of unseen videos for testing.
  • BAS-specific activities should be defined according to the actual experiment procedure.

RECOMMENDED DEVELOPMENT DATASET

  • Begin with approximately 10–20 varied videos per activity for an initial prototype.
  • Increase the number of examples as the activity vocabulary grows.
  • Use the configured train/validation/test split.
  • Evaluate using videos that were not used during training.

Why "Unknown"?

BAS-HAR applies confidence filtering to avoid treating uncertain predictions as reliable classifications. When the predicted confidence falls below the configured threshold, the interface can report Unknown. This is particularly important for the development phase because the current model contains generic activity classes and is not yet a fully trained BAS-specific model.
